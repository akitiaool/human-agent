# 工作区一等化与权限模型修订（2026-10-11）

工作区从「启动 CWD 注册的默认信任面」升级为**一等概念**（显式指定、启动规范化、进程级不可变）；权限模型从「两模式（默认 / 自动授权）」修订为**三档未信任处置（默认弹窗 / 默认拒绝 / 默认允许）**；新增**信任候选**档案（桥自记白名单外一切裁决，面板可单选/多选一键入库）；路径类匹配统一走**规范匹配键管道**（resolve → realpath 深度归实 → win32 小写），修复相对路径穿越、相对路径误判、读类无信任三个实证缺陷。

本设计**修订** `2026-08-20-permission-model-design.md` 的 §2（裁决矩阵）、§3（匹配串规范）、§4（白名单）、§6（工作区绑定）、§7（审批弹窗与协议演进）、§12（文件存储）、§15（已知限制）；架构文档 v1.0.0 行 18（「眼睛无需安全审批」）同源过期。历史文档本体不动，以本 spec 为准。

## 1. 背景与缺陷实证

三条缺陷均经代码级逐行推演实证（涉及 `policy.ts` 的 `resolvePathSegments`/`matchKeyFor`、`blacklist.ts` 写形态、`reflection.ts`/`policy.ts` 读类裁决）：

| # | 探针 | 现行为 | 缺陷 |
|---|---|---|---|
| ① | 写 `..\..\..\..\..\Windows\System32\evil.exe`（相对穿越，CWD 够深时落点为 `C:\Windows\System32\evil.exe`） | 匹配键 = `windows/system32/evil.exe`（`..` 无基准被吞、无盘符）→ 黑名单写形态（锚定 `^[a-z]:/windows/...`）不命中 → 自动授权模式**静默执行** | 黑名单绕过：相对穿越写入 System32 无任何拦截 |
| ② | 写 `src/foo.ts`（工作区内，相对形态） | 匹配键 = `src/foo.ts` 字面 → 与工作区绝对路径条目不匹配 → unlisted → 默认模式**误弹窗** | 相对路径不可信：界内写入被当界外 |
| ③ | 读界内 `src/a.ts`、读界外 `D:\secrets.txt` | 二者均 unlisted → 默认模式全部弹窗 | 读类无路径级信任：读也成为噪音源 |

匹配键产生时**脱离工作区基准做纯词法归一**，是 ①② 共同根源——裁决基准与真实执行落点脱节。

目标：

- 工作区一等化——显式指定、启动 realpath 规范化（junction 别名收敛同一分节）、一进程一工作区不可变；
- 裁决与执行同基准——「执行落点 = 判定落点」成为不变式；
- 读类纳入路径级信任（写信任蕴含读）；
- 三档未信任处置覆盖无人值守/给足权限两种运营姿态；
- 信任候选档案让「首次运行被拒/被放行」能收敛为白名单成长，不依赖用户记忆。

沙盒（进程/文件系统真隔离）本轮**不做**，Docker 路线见 §11。

## 2. 工作区一等化

### 2.1 指定与规范化

- 优先级：**`--workspace <path>` > 环境变量 `HUMAN_AGENT_WORKSPACE` > 启动 CWD**。
- 相对值按 CWD 解析；启动时 **realpath 规范化**（junction/symlink 别名收敛——`C:\alias-ws` 与 `C:\real-ws` 落同一白名单分节）。
- 必须是**已存在的目录**，否则友好报错退出（exit 1，两类模式一致）。
- 规范化发生在启动组装（CLI 解析 → agent 构建），policy 接收已规范化路径（内部仍走 normalizePath 兜底）。
- **一进程一工作区，不可变**；切换工作区 = 重启进程。（列出/切换多工作区的清单功能见 §11。）

注意：`--workspace` 与 pnpm 递归过滤旗标同名——文档指引写 `pnpm dev -- --workspace X`（透传）或直接用 `HUMAN_AGENT_WORKSPACE`。

### 2.2 隔离结构（成文）

| 层 | 粒度 | 说明 |
|---|---|---|
| 黑名单 | 通用定死 | 确定性系统破坏，跨工作区一致，不可配 |
| 白名单 | 按工作区绝对路径分节 | 现状不变（`~/.human-agent/whitelist.json`） |
| 信任候选 | 按工作区绝对路径分节 | 新增（`~/.human-agent/candidates.json`，见 §7） |
| 工作区 | 进程级 | 启动自动注册写 path-dir 条目 = 默认信任面 |

### 2.3 呈现

- CLI 启动横幅打印当前工作区（Ollama REPL 与桥模式一致；桥模式随监听地址一并打印）。
- 桥新增 **`GET /info`**（无状态幂等）：`200 {ok, workspace}`；服务 close 后 204（同 `/protocol` 模式）。
- 扩展面板显示当前工作区（启动时经 `GET /info` 取得；具体位置与时机实现定）。

## 3. 规范匹配键管道

路径类参数一律经统一管道产生**执行路径与匹配键**：

```
resolveWorkspacePath(input, workspace) → { execPath, matchKey } | null（失败）
```

1. `path.resolve(workspace, input)` 词法绝对化（`..` 有基准可正确消解——修复①的吞段问题）；
2. **realpath 深度归实**：找最深已存在祖先 → `realpath` 之 → 拼回剩余段（不存在的尾段不参与归实）；
3. win32 小写、正斜杠形式 → `matchKey`；`execPath` 保留 realpath 规范大小写（执行用）。

- **失败（realpath 错误等）→ 返回 null，调用方按未信任处置；绝不回退纯词法结果**。
- terminal 命令串**不适用**本管道（命令是文本，黑名单仍按命令串模式匹配；命令串内的相对形态不在黑名单覆盖——文本层限制，见 §11，默认允许档对此明示）。
- 黑名单模式本身不改：canonical 键使探针①直接命中写形态（`c:/windows/system32/evil.exe`）。**两条写形态（`System32`/`Boot` 子树、`System Volume Information`）限定仅写类工具命中**——读类进入路径维度后，读 System32 不做黑名单硬拒，走信任门禁。

**`matchKeyFor` 修订**（工具 → 匹配键）：

| 工具 | 匹配键 |
|---|---|
| terminal | `normalizeCommand(命令串)`（现状不变） |
| WRITE_TOOLS（write_file / apply_patch / edit_file） | `resolveWorkspacePath(path, workspace).matchKey` |
| READ_TOOLS（read_file / read_dir / search_code） | 同上（仅取 `path` / `dir` 参数；行区间、pattern 等不进信任；`search_code` 的 `dir` 缺省 = 工作区根） |
| fetch_page | `serializeArgs` 全参数 exact（现状不变） |

**`keyMatches` 修订**：目录条目（尾 `/`）命中的目标增加**条目自身路径**——`w/` 同时匹配 `w`（覆盖 `read_dir` 读工作区根、`covers` 同判）：

```
entry.key.endsWith("/") → key === entry.key || key === entry.key.slice(0, -1) || key.startsWith(entry.key)
```

**归一职责上收**：路径类白名单条目的归一以桥侧 §3 管道为准；扩展提交的载荷 key 只作近似展示，桥归一 + 形态复核（含「目录条目根级降级为文件条目」既有规则复核）+ 对应性校验后才落盘（见 §7.3）。

**旧条目兼容注记**：存量白名单条目（相对 / 词法 / 无盘符 / 大小写不一）在新管道下可能不再命中，后果 = 该调用重新按未信任处置（弹窗 / 默认拒绝档拒绝），用户可重新入库。**不做自动迁移**（安全向）。

## 4. 读类路径级信任

- `read_file` / `read_dir` / `search_code` 进入路径维度（§3 管道产生 matchKey）；`fetch_page` 维持全参数 exact。
- **方向 = 写信任蕴含读**：

| 条目工具 | 命中调用 |
|---|---|
| WRITE_TOOLS | WRITE_TOOLS ∪ READ_TOOLS（path 条目跨写读工具共享，「允许写 src/」同时意味「允许读 src/」） |
| READ_TOOLS | 仅 READ_TOOLS |
| terminal / fetch_page | 仅同工具（exact，现状不变） |

- **读无黑名单硬拒**（读无破坏性）；界外读由信任门禁兜住（未信任 → 按档位处置）。界内读因工作区写 path-dir 条目 + 写蕴含读，**默认静默**。
- 交互面同步（当前均缺读类 path 粒度）：
  - 扩展弹窗：读类调用提供 [允许本次] [拒绝] + 路径两粒度 [白名单(此路径)] [白名单(此目录)]；
  - CLI 嘴巴 `askApproval`：读类同样两粒度；
  - 桥 `POST /approval` 的 `whitelist` 校验：接受读类 path 条目（文件条目 = 调用路径自身 matchKey；目录条目 = 父目录 + "/" 前缀，沿用现有两粒度规则）。

## 5. 三档未信任处置

「未信任调用」（黑名单不命中、白名单不命中）的三种去向，**单轴三档**，面板一个三态选择器：

| 档位 | 未信任调用去向 | 人在环内 | 说明 |
|---|---|---|---|
| **默认弹窗**（默认） | 下发审批逐条问：允许本次 / 拒绝 / 入库 | 是 | 桥：扩展弹窗（120s 倒计时自动全拒）；CLI：嘴巴三选。现状行为 |
| **默认拒绝** | 即时拒绝 + 桥标准拒绝文案回填（桥不感知档位；档位说明呈现在面板侧日志） | 否 | 唯一**不依赖人**的确定性档；适合无人值守（即时回决，无弹窗倒计时空耗） |
| **默认允许** | 即时放行 | 否 | 无策略、放弃边界，黑名单兜底；给足权限理念的保留档 |

- **黑名单三档一致硬拒**（直接拒绝回填，不下发审批，现状不变）。
- 无人值守（默认拒绝/默认允许）的前置条件 = **预种信任面**（白名单先配好或事后用候选补种）。
- 实现 = **扩展侧三应答策略**（弹窗 / 整体回拒 / 整体回允许），桥的审批链路零改动、`GET /task`+`POST /approval` 协议不变。
- **档位归属：桥没有档位概念**——桥的视角恒为「未信任 → 下发审批 → 收到一个裁决」，三档只是扩展宿主对「回执如何产生」的三种通道策略（人答 / 策略代答拒绝 / 策略代答放行）。档位概念不出现在协议、桥代码、候选记录（`denied`/`allowed` 计数不标来源：人工裁决、倒计时全拒、档位代答、600s 超时同形）与白名单/黑名单文件中。CLI 宿主恒为弹窗（嘴巴三选），不涉及档位。
- 面板「自动授权危险命令」开关（autoApprove）**替换为三态选择器**（副文案：默认拒绝 = 未信任一律拒绝，适合无人值守；默认允许 = 未信任一律放行，仅黑名单拦截）。默认允许档启用时面板**常显警示标识**。
- **迁移**：设置载入时一次性映射 `autoApprove: true → 默认允许`、`false → 默认弹窗`（行为不变），此后按三态选择器运行。
- 命名裁定：三档以「未信任去向」命名（默认弹窗/默认拒绝/默认允许），不用「自动模式」包装（旧口号「免弹窗≠免边界」退休；「无人值守」降格为场景描述，建议选默认拒绝）。

## 6. 执行一致性

- **不变式：执行落点 = 判定落点**。路径类调用经 §3 管道产生 `execPath`（绝对、realpath 归实），**传递至执行器/器官**使用；回填与展示仍用**原始参数文本**（用户看到模型原话）。
- **terminal cwd 钉到工作区**（execa `cwd` 选项；Terminal 构造注入或调用透传，实现细节留给 plan）——relative 命令目标落在工作区，与工作区概念一致。
- 器官不再自行解释相对路径（相对形态在 §3 管道已绝对化）。

## 7. 信任候选（Trust Candidates）

**定位**：白名单外一切裁决的持久记录，供面板查看与**单选/多选一键入库**。默认拒绝档 = 补种清单（首跑被拒 → 看候选 → 入选 → 再跑）；默认允许档 = 放行审计（事后收拢边界）。收敛闭环让「信任面成长」不依赖用户记忆。

### 7.1 记录范围

| 事件 | 是否入档 |
|---|---|
| 弹窗档：放行本次 / 拒绝（含 120s 倒计时自动全拒） | 入 |
| 默认拒绝档：自动拒绝 | 入 |
| 默认允许档：自动放行 | 入 |
| 审批 600s 兜底超时（桥侧） | 入（拒绝） |
| 黑名单命中 | 不入 |
| 白名单命中 | 不入（对应候选在入库时核销移除，见 §7.3） |
| 入库动作本身 | 不入（入库即核销，避免同条既在白名单又留候选） |
| `close()` 释放的挂起审批 | 不入（非用户裁决，属关闭噪音） |

### 7.2 桥自记（关键架构）

桥在审批流**必经之路**上（含扩展看不见的 600s 兜底超时），因此**桥自记、扩展退化为视图**。两个记录钩子（均现成代码点）：

1. `#handleApprovalRequest` 校验通过后：按 `allowed` 逐条记 allowed/denied；带 `whitelist` 的调用 → 条目落盘 + **对应候选核销移除**；
2. `#requestApproval` 600s 超时 settle 全拒时：记 denied（`timedOut`）。

**运作时序（三档一致——扩展从不发送候选记录，记账是桥的本地磁盘更新，无额外网络请求）**：记账发生在**裁决落地的那一刻**——弹窗档 = 收到用户裁决的 `POST /approval` 时；默认拒绝/允许档 = 扩展按应答策略立即回执时（同一端点，桥无需感知档位）；600s 超时 = 桥侧 settle 时。审批下行（`GET /task`）与回执上行（`POST /approval`）本就存在，「记录」不引入任何新流量。粒度 = **批**（一条模型回复中的未信任调用集合）：批内每条调用对 `(tool, key)` 聚合计数 +1、更新 `lastSeen`（同条被拒十次 = 一条 `denied: 10`，非十条流水）；同批静默放行（白名单命中）的调用不进审批、不入档。面板为**拉取方**（展开时 + 操作后 `GET /candidates`），桥不推送。

档案 `~/.human-agent/candidates.json`，**镜像 whitelist.json 按工作区分节**（浏览器全局存储混工作区的问题从根上消失）：

```json
{
  "/path/to/workspace": [
    { "tool": "write_file", "key": "c:/ws/src/foo.ts",
      "denied": 2, "allowed": 1,
      "firstSeen": "<ISO>", "lastSeen": "<ISO>" }
  ]
}
```

- 聚合键 = `(tool, matchKey)`；损坏降级空白、落盘失败不崩溃（同白名单惯例）。
- 容量帽：**200 条 / 30 天**，超限按 `lastSeen` 丢最旧。

### 7.3 端点

| 端点 | 语义 |
|---|---|
| `GET /candidates` | `200 {ok, candidates:[{tool, key, denied, allowed, firstSeen, lastSeen}]}`；返回前**滤除已被白名单覆盖**的陈旧条目（未 dismiss 的遗留不显示）；close 后 204 |
| `POST /whitelist` | 入参 `{entries:[{tool, key, kind}]}`；**全量校验 all-or-nothing**：形态合法 → 工具与粒度匹配（路径类工具限 path 文件/目录，terminal/fetch_page 限 exact）→ 经 §3 管道归一 → 对应现存候选（目录粒度 = 段级前缀对应）→ 入库复核（含根级降级）；成功后**核销移除**对应候选；任一不合法 400，全部不落盘 |
| `POST /candidates/dismiss` | 入参 `{items:[{tool, key}]}`；清除所选（持久化删除），不写白名单 |

必须**新增 `/whitelist` 独立端点**：现有 `POST /approval` 的 whitelist 字段校验绑定「本批 allowed=true 的调用」，塞不进「事后按候选补种」。

### 7.4 面板 UI

- 折叠区「**信任候选 (N)**」（计数徽标），**默认折叠**；
- 行 = 复选框 + 工具 + 键（**单行省略号**，悬停显示全量）+ 计数（拒 a / 放 b）+ 最近时间；**行内无按钮**（防撑变形）；
- 区底操作栏：`[全选]` `粒度: [文件|目录]`（**仅作用于路径类行**，默认**文件级**窄默认；terminal/fetch_page 行恒 exact）`[入库所选 (n)]` `[清除所选]`；
- 区体**固定高度约 140px 滚动**；刷新时机 = 展开时 + 操作后（可轻轮询）；
- 日志摘要行（如 `[信任候选] +5（默认拒绝）`）；
- 无需面板导出（档案即磁盘文件，用户可直接查看）；
- CLI 暂不记候选（未来方向）。

## 8. 面缝收口

同一概念多处镜像的缺口一并收口，避免「一处改、多处漏」：

1. **`WRITE_TOOLS` 从 `policy.ts` 导出为单一来源**（现为模块内私有常量），`loop.ts` 等引用；修复 `loop.ts` 写类判定漏 `edit_file`（现仅 `write_file`/`apply_patch`）。新增 `READ_TOOLS` 同源导出。
2. **扩展镜像集同步**（content.js）：`normalizeKey` 写类分支补 `edit_file` + 读类工具；弹窗行按钮的 isWrite 判定同步引用；弹窗标题/提示文案泛化（现文案「危险命令授权」「该命令可能删除或覆盖数据」仅适配写类——读类调用需对应提示语）。
3. 扩展侧白名单载荷仅作近似归一（展示用），落盘归一以桥为准（§3）。

| policy | 相对穿越硬拒（探针①：`..\..\..`→System32 canonical 键命中黑名单写形态）、相对界内静默（探针②）、界外读 pending（探针③）、链接穿墙（junction/file symlink 指向界外 → realpath 归实后 unlisted）、realpath 失败 → 未信任（不落词法）、方向性（写条目命中读 / 读条目不命中写）、目录条目自身匹配（`w/` 匹配 `w`）、读类 matchKey（行区间/pattern 不进键、dir 缺省=工作区根）、读类 buildWhitelistEntry、两写形态仅写类命中（读 System32 不硬拒）、旧词法条目失效 → 重新弹窗 |
| reflection | 读界内 allowed、读界外 pending |
| loop | edit_file 写类审批（WRITE_TOOLS 修复的回归）、读类两粒度三选 |
| 桥 | `GET /info`（200/close 后 204）、两记录钩子（决策入档 / 600s 超时入档 / 入库核销 / close 不清算）、聚合与容量（帽 200/30 天）、`GET /candidates` 滤除已覆盖、`POST /whitelist` 全量原子性（含 dir 前缀对应、非法一项 400 全不落）、`POST /candidates/dismiss`、`/approval` 读类 whitelist 校验接受、默认拒绝档回填文案 |
| 执行一致性 | 相对路径落点 = 裁决基准（execPath 传递）、terminal cwd 钉工作区 |
| 扩展 | 真实浏览器 E2E（惯例：三档行为、候选区交互、迁移映射），无测试框架 |

## 11. 未来方向与已知限制

**未来方向（只入文档，不实现）**：

- **Docker 沙盒**（进程/文件系统真隔离；Windows 无原生沙箱的替代路线）；
- 工作区清单与**运行中切换**（现为一进程一工作区，切换=重启）；
- 数据隔离（key/DB 命名空间）、进程隔离；
- 网络出口边界（`fetch_page` 当前**无 URL 校验、无超时**）；
- 多根工作区；
- CLI 侧候选记录与查看。

**已知限制**：

- 文本层限制：terminal 命令串内的相对形态 / 混淆不在黑名单覆盖（`bash -c`、PowerShell 混淆同 2026-08-20 spec §15）；**默认允许档明示此风险**（该档语义即黑名单兜底 + 文本层判定）。
- 无 OS 沙箱（Windows，延续 2026-08-20 §15 立场）。
- Windows 路径别名边缘残留（8.3 短名、尾点/尾空格等非常规名，realpath 归实覆盖大部分但非全部）。
- 旧白名单条目在新管道下可能失效 → 降级方向为重新弹窗（§3 注记）。
