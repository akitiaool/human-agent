# gemini-bridge 浏览器扩展（v3 网络原文捕获 · 网页对话驱动）

human-agent 与 AI Studio 网页版 Gemini 之间的桥。**对话发生在网页**
（Google AI Studio），智能体仅执行工具。插件做三件事：

1. **网络原文捕获**：页面主世界（MAIN world）薄 hook 拦截 GenerateContent 响应流，
   取**未渲染的模型原文**解码后 POST 给本机桥服务（`POST /result {reply}`），
   桥服务解析 ```tool_call``` 交给智能体执行。完成捕获**统一走快照取证**：同一判据
   （`responseText` 构成完整 JSON）在三个同步点调用（rs=3/4 事件到达时、页面 `abort()`
   调用前、loadend 兜底），done 只承载完整 JSON、截断/非文本就地转 error——AI Studio
   会在流完成瞬间调用 `abort()`，abort 放行后状态与 `responseText` 立即按规范清空、
   完成事件可能一件都不发，快照在三个同步点内抢先取走原文，不依赖任何完成事件。
   DOM 抓取通道已整体删除——
   渲染失真不可靠；捕获失手时任务「响亮停滞」（面板不再出现「已回传」日志，
   一眼可诊、可修复），绝不降级产出错值；
2. **投递回填**：长轮询桥服务（`GET /task`）取回填消息（工具执行结果），
   **模拟人类分段粘贴输入**（分段粘贴 + 错别字纠错）到页面输入框，「自动提交回填消息」开（默认）
   则随机延迟后自动点击发送，关则只回填、由你手动点页面发送按钮；
3. **协议注入**：从桥服务按需拉取协议文本（`GET /protocol`，无本地存储）。
   「新对话自动注入协议」开关（默认开）控制自动注入：会话切换以 **URL 变化**为检测信号
   （每 400ms 对比地址；历史对话 `/prompts/<id>` 逐对话唯一，空对话 `/prompts/new_chat`），
   **仅新对话页且对话为空**（轮次计数 0、双采样确认）自动注入；
   **页面加载不自动检查**（防刷新旧对话渲染期误判为空导致重放）。
   任何对话、任何开关状态下都可用面板「填入规则文本」按钮手动注入（无条件）。

整个流水线内容驱动、无 id 握手：`网页回复 → 桥服务解析执行 → 回填消息 → 网页提交 → 新回复…`
（去重由服务侧兜底，重复提交返回 `processed: false`）。

扩展文件：`manifest.json`（v0.3.0）、`background.js`（全 try/catch 中转）、
`inject.js`（MAIN world 捕获层，document_start）、`decode.js`（响应流解码，纯函数）、
`content.js`（隔离世界接入层：面板 / 投递循环 / 审批弹窗 / 新对话检测）。

## 前置条件

- Chrome / Edge（Chromium 内核）
- 本机已启动 human-agent 桥服务（默认 `127.0.0.1:8765`），建议手动验证：
  ```bash
  GEMINI_BRIDGE_PORT=8765 pnpm dev
  ```
  可另开终端确认服务可访问：`curl http://127.0.0.1:8765/task`（约 25s 后返回空 204）、
  `curl http://127.0.0.1:8765/protocol`（立即返回协议文本 JSON）。

## 安装

1. 浏览器打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录（`extensions/gemini-bridge`）

## 使用步骤

1. 先启动桥服务（见上），再打开 https://aistudio.google.com 并进入对话页；
2. 确认页面右下角出现 gemini-bridge 浮动面板（状态「待命」）；
3. 「新对话自动注入协议」开启（默认）时，**切换或新建对话**后（URL 变化自动检测）
   插件检查当前对话是否为空：空对话页自动从桥服务拉取协议文本并回填
   （「自动提交回填消息」开则随后自动发送），对话应以工作区声明开头（其后为【human-agent 工具协议】）；
   已有消息的对话跳过不注入（防旧对话重放）。开关关闭、或**刷新页面后**（不自动检查），
   点面板「填入规则文本」手动注入；
4. 之后对 Gemini 的对话都会形成「回复 → 智能体执行工具 → 结果回填 → 提交」循环；
5. 任务完成或无需工具时 Gemini 直接输出最终回答，流程结束。

## 面板设置

「自动提交回填消息 / 新对话自动注入协议 / 自动授权危险命令」为三项**独立开关**（面板中归为「自动模式」组），可任意组合。

| 设置 | 说明 |
|---|---|
| 自动提交回填消息 | 开（默认）：回填后随机延迟（防检测区间）自动点击发送；关：只回填，由你手动点页面发送按钮 |
| 新对话自动注入协议 | 开（默认）：切换到空的新对话页时自动拉取协议文本注入（自动提交开启则随后自动发送）；关：任何对话都不自动注入，用「填入规则文本」按钮手动注入 |
| 模拟人类输入 | 开：**分段粘贴 + 错别字纠错**（整段粘贴模拟 Ctrl+V，按概率预留错字 → 退格删除 → 停顿想字 → 逐字重打，段间随机停顿，纠错全程按真人键入节奏：纠错前停顿 1–2.5s、退格 150–450ms/次、重打 200–500ms/字）；关：一次性填入 |
| 提交延迟（秒，min/max） | 自动提交前的随机延迟区间，默认 3–8 秒；min>max 时自动对调 |
| 分块长度（字符，min/max） | 模拟输入时每块粘贴长度在区间内逐块随机（默认 2–1024，可调 2–1024，min>max 自动对调），避免等长分段暴露自动化；剩余不足 min 时并入前一块收尾 |
| 回填速度 | 回填节奏倍率（0.5x / 1x / 2x / 4x / 10x），默认 1x。**回填过程中修改立即生效**（每步停顿按当前倍率实时缩放；已切分好的块长度本次不变） |
| 自动授权危险命令 | 开：收到审批请求静默放行不弹窗；关（默认）：弹窗人工授权 |
| 审批超时（秒） | 弹窗倒计时，到点自动全部拒绝；默认 120，可调 10–600 |
| 纠错概率（%） | 每段触发「粘贴错字→退格→重打」纠错的概率，默认 40%，可调 0–100 |
| 桥服务地址 | 默认 `http://127.0.0.1:8765`，可改（纯端口如 `9876` 亦可）；改动后保存在 `chrome.storage.sync` |

面板交互：标题栏**按住可拖拽**（悬浮球同样可拖），右上角 **–** 按钮收起为**悬浮球**（仅保留状态圆点，双击展开完整面板）；收起/展开时位置保持，扩展功能不受面板状态影响。日志栏带**导出**（下载为 `.log` 文本文件）与**清除**按钮；自动提交前状态行显示**动态倒计时**（逐 0.1s 递减）；「自动提交回填消息」行右侧的**「立即提交」按钮**无条件提交输入框当前内容（非空即提交、无论内容是回填还是用户自输入；输入框为空或回填进行中时按钮置灰禁用）。面板/悬浮球为边框样式，原生控件（数字输入 spinner、select 下拉、滚动条）走暗色绘制。

## 权限模型

所有工具调用一律走服务端统一黑白名单裁决（`PermissionPolicy`），扩展只呈现审批交互：

| 模式 | 裁决 |
|---|---|
| 默认（从严） | 黑名单直接拒绝（不下发审批）→ 白名单命中静默执行 → 其余全部下发审批弹窗，逐条人工授权 |
| 自动授权（面板开关） | 黑名单外全部放行（审批请求仍下发，面板开关决定弹窗或静默全允许） |

- **黑名单**：内置随软件版本（`src/nose/blacklist.ts`），只拦**确定性系统破坏**操作——系统盘/根目录递归删除、格式化、整盘擦除、块设备直写、Boot 关键文件/注册表、杀之必崩进程，以及写类工具写系统目录（path 匹配锚定 `System32`/`Boot` 子树）等；目标锚定（`rm -rf C:\Windows\Temp` 等可恢复目标不入），用户可手改该文件（责任自负，升级被覆盖属已知行为）。命中直接拒绝回填「已拒绝（BLACKLIST：系统破坏操作，禁止执行）」，**不下发审批**。
- **白名单**：`~/.human-agent/whitelist.json`，按工作区绝对路径分节；条目 `{ tool, key, kind }`——`exact` 匹配命令/参数整串（如 `git status`）；`path` 匹配写类路径，目录条目以 `/` 结尾**段级前缀**覆盖子树（`src/` 覆盖 `src/utils.ts`、不覆盖 `src-evil/`），对 write_file 与 apply_patch 跨工具生效；写入时自动冗余清理（加父去子、子被父盖跳过）。
- **工作区**：启动 CWD 自动注册为写白名单 path-dir 条目（界内写入静默）；工具协议文本以**工作区声明**开头（其后为【human-agent 工具协议】），告知智能体活动边界（软约束）。
- **弹窗按钮**：逐条 [允许本次] [拒绝] + 白名单动作——非写类 [加入白名单（exact）]、写类 [白名单(此路径)] [白名单(此目录)]（目录条目 = 父目录段级前缀）；「全部允许 / 全部拒绝」保留（全部允许不自动入白名单——白名单始终是显式按钮动作）；白名单条目经 `POST /approval` 的 `whitelist` 字段带回，桥侧校验（必须对应本批 `allowed=true` 的调用）后落盘。
- 弹窗倒计时到点自动全部拒绝（回填「审批超时，未执行」）；审批请求在桥服务侧另有 600s 兜底超时（防扩展崩溃）。

**状态标准**（跨网页通用：这套状态机描述「捕获 → 后端执行 → 回填 → 提交」桥流水线，与具体前端无关，
将来接 ChatGPT 等其他网页可复用同一套；自动/手动提交的差异只体现在「待提交」阶段的渲染上）：

| 阶段 | 显示 | 颜色 |
|---|---|---|
| 静息 | 待命 | 蓝 |
| 回填 | 回填中（模拟粘贴） | 橙 |
| 待提交 | 自动：自动提交（Xs 后）倒计时；手动：待提交（手动发送） | 绿 |
| 回复在途 | 等待回复（请求发出即置位，原文到手结束） | 紫 |
| 后端处理 | 已抓取回复（等待执行） | 青 |
| 审批 | 等待授权 | 琥珀 |
| 桥故障 | 桥未连接（重试中） | 琥珀 |
| 异常 | 错误（投递循环空闲时清回待命） | 红 |

状态行文字与右侧**呼吸灯**、悬浮球圆点同色，均带呼吸律动动画。

**注意**：请只在一个 AI Studio 标签页使用本扩展；多个标签页会竞争轮询同一条回填消息。

## 排查

| 现象 | 可能原因 / 处理 |
|---|---|
| 面板状态「错误」，日志显示取任务失败 | 桥服务未启动（先 `GEMINI_BRIDGE_PORT=8765 pnpm dev`）；端口占用（换端口后同步改面板「桥服务地址」与 `manifest.json` 的 `host_permissions`） |
| 回填后输入框无反应 / 无法提交 | 页面未在对话页（无 `ms-prompt-box textarea`）；或页面 DOM 结构更新导致选择器失效 |
| 回填失效（未找到输入框/发送按钮） | 打开 DevTools 检查元素，更新 `content.js` 顶部选择器常量区域：输入框 `ms-prompt-box textarea.cdk-textarea-autosize.textarea`、发送按钮 `ms-run-button button[type="submit"].ms-button-primary`。AI Studio 为 Angular SPA + 虚拟滚动，元素频繁创建/销毁，抓取必须每次现查 DOM |
| 回复不再回传（无「已回传」日志） | 响亮停滞诊断：无「网络捕获已挂载」→ 注入层未生效（Chrome < 111 不支持 `world:"MAIN"`；或扩展代码更新后未刷新 AI Studio 页面，content script 不热重载）；有「检测到 GenerateContent 请求」但无「已回传」→ 解码失败（看「解码失败（原文 N 字符）」日志）或 AI Studio 端点迁移（更新 `inject.js` 的 URL 命中判据）。**捕获链路逐环可诊**：浏览器控制台过滤 `[ha-capture]` 可见全链路（open 命中 → send 命中 → readyState 轨迹 → 快照兜底（rs3/rs4/abort/loadend 来源标签）→ done），断在哪一环一目了然；出现「readyState 归零」或「abort() 在原文到手前被调用」（附调用栈）警告 = 请求对象在原文到手前被页面重置、本次捕获被吞——携警告与调用栈报告 |
| 插件加载时报错 | `chrome://extensions` 页面点「错误」查看 background 日志；确认四个文件（background.js、content.js、inject.js、decode.js）无语法错误 |
| 新对话后协议文本未注入 | 先确认「新对话自动注入协议」开关为开（默认）。开启时自动注入由**会话切换**触发（URL 变化检测）且仅在**新对话页**（地址为 `/prompts/new_chat`、轮次计数 0、双采样确认；轮次不计思考）时执行；**刷新页面后不自动检查**，请点面板「填入规则文本」（任何开关状态下都可用）。日志「保守等待渲染…」= 新对话页出现会话容器（首条消息提交过渡态），稍候或手动注入。拉取失败原因见日志：桥未启动 / 旧版桥服务无 `/protocol` 端点（需重启桥服务加载新代码）|

**扩展重载**：修改扩展代码后需在 `chrome://extensions` 点刷新，并**刷新 AI Studio 页面**（content script 不热重载），否则仍跑旧代码。

## 安全

权限矩阵保证**无人值守也安全**：黑名单（确定性系统破坏）两模式一致直接拒绝、不下发审批；默认模式
未入白名单的调用必须经弹窗人工授权（面板可开自动授权静默放行），拒绝/超时说明随结果消息回填；
弹窗倒计时到点自动全部拒绝，审批请求在桥服务侧另有 600s 兜底超时（防扩展崩溃）。
