# gemini-bridge 浏览器扩展（v0.4.0 · 网络原文捕获 · 网页对话驱动）

human-agent 与 AI Studio 网页版 Gemini 之间的桥。**对话发生在网页**
（Google AI Studio），智能体仅执行工具。插件做三件事：

1. **网络原文捕获**：页面主世界（MAIN world）薄 hook 拦截 GenerateContent 响应流，
   取**未渲染的模型原文**解码后 POST 给本机桥服务（`POST /task/reply {reply}`），
   桥服务解析 ```tool_call``` 交给智能体执行。完成捕获**统一走快照取证**：同一判据
   （`responseText` 构成完整 JSON）在三个同步点调用（rs=3/4 事件到达时、页面 `abort()`
   调用前、loadend 兜底），done 只承载完整 JSON、截断/非文本就地转 error——AI Studio
   会在流完成瞬间调用 `abort()`，abort 放行后状态与 `responseText` 立即按规范清空、
   完成事件可能一件都不发，快照在三个同步点内抢先取走原文，不依赖任何完成事件。
   DOM 抓取通道已整体删除——
   渲染失真不可靠；捕获失手时任务「响亮停滞」（面板不再出现「已回传」日志，
   一眼可诊、可修复），绝不降级产出错值；
2. **投递回填**：长轮询桥服务（`GET /task`）取回填消息（工具执行结果），
   **模拟人类分段粘贴输入**（分段粘贴 + 错别字纠错）到页面输入框，「自动提交回填消息」开（默认）
   则随机延迟后自动点击发送，关则只回填、由你手动点页面发送按钮；
3. **协议注入**：从桥服务按需拉取协议文本（`GET /agent/protocol`，无本地存储）。
   「新对话自动注入协议」开关（默认开）控制自动注入：会话切换以 **URL 变化**为检测信号
   （每 400ms 对比地址；历史对话 `/prompts/<id>` 逐对话唯一，空对话 `/prompts/new_chat`），
   **仅新对话页且对话为空**（轮次计数 0、双采样确认）自动注入；
   **页面加载不自动检查**（防刷新旧对话渲染期误判为空导致重放）。
   任何对话、任何开关状态下都可用面板「填入规则文本」按钮手动注入（无条件）。

整个流水线内容驱动、无 id 握手：`网页回复 → 桥服务解析执行 → 回填消息 → 网页提交 → 新回复…`
（无工具调用的回复返回 `processed: false`，本轮自终止；同一内容重复提交照常执行——重复控制归模型侧）。

**零手抄**：扩展不含任何工具名、键归一、条目构造逻辑——审批白名单按钮按桥下发载荷
`options[i]` 渲染（两项 → [白名单(此路径)]/[白名单(此目录)]，一项 → [白名单]，零项 → 无按钮），
所选条目**原样回显**并入审批回执；候选入库只发 `{items, scope}`，条目由桥服务物化并校验。

扩展文件：`manifest.json`（v0.4.0）、`background.js`（八路信封中转，全 try/catch）、
`inject.js`（MAIN world 捕获层，document_start）、`decode.js`（响应流解码，纯函数）、
`content.js`（隔离世界接入层：面板 / 投递循环 / 审批弹窗 / 新对话检测）。

## 前置条件

- Chrome / Edge（Chromium 内核）
- 本机已启动 human-agent 桥服务（默认 `127.0.0.1:8765`），建议手动验证：
  ```bash
  GEMINI_BRIDGE_PORT=8765 pnpm dev
  ```
  可另开终端确认服务可访问：`curl http://127.0.0.1:8765/task`（约 25s 后返回裸 204）、
  `curl http://127.0.0.1:8765/agent/protocol`（立即返回信封 `{"status":"ok","data":{"protocol":"…"}}`）、
  `curl http://127.0.0.1:8765/agent/info`（返回 `data.workspace`）。

## 桥服务端点（wire v1）

**统一信封**（每响应一封）：成功 `{status:"ok", data?}`；失败 `{status:"error", error:{code, message}}`。
**裸 204 仅用于空长轮询**。传输错误码（closed）：`invalid-body` / `unknown-endpoint` /
`method-not-allowed` / `unknown-approval` / `internal`（对应 HTTP 400 / 404 / 405 / 404 / 500），
message 为中文人话。**域失败永不抬升为信封失败**（如命令执行超时：信封仍 `status:"ok"`，
`data` 内域结果自带错误码）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/task` | 长轮询（约 25s）：200 信封 `data:{type:"message", message}`（回填消息）或 `data:{type:"approval", id, calls, options}`（审批请求）；无消息 → 裸 204 |
| POST | `/task/reply` | `{reply}` → `data:{processed}`（`processed:false`＝回复无工具调用，本轮自终止） |
| POST | `/task/approval` | `{id, allowed: boolean[], whitelist?: TrustEntry[]}` → 200 空回执；id 未知/已结 → 404 `unknown-approval` |
| POST | `/permission/whitelist` | `{items:[{tool, key}], scope:"self"\|"subtree"}` → `data:{grants:[{entry, add:{status}, retired}]}`；全量原子校验：任一非法 → 400 `invalid-body`（整批不落盘） |
| GET | `/permission/candidates` | `data:{candidates:[…]}`（白名单外裁决的持久记录，已滤除被白名单覆盖项） |
| POST | `/permission/candidates/dismiss` | `{items:[{tool, key}]}` → `data:{dropped}` |
| GET | `/agent/protocol` | `data:{protocol}`（工作区声明 + 工具协议文本，无状态按需） |
| GET | `/agent/info` | `data:{workspace}`（当前工作区） |

**审批载荷 `options`（零手抄载体）**：`options[i]` 是第 i 条待授权调用的合法白名单选项数组，
由桥侧预构造——路径类 2 项（此路径 `self` / 此目录 `subtree`）、其余 1 项、目标无法解析时 0 项。
扩展只按数量渲染白名单按钮并**原样回显**所选条目；桥侧按批校验（回显条目必须与某条
`allowed=true` 调用的选项成员逐字段一致，否则 400 且整批不落盘）。

**扩展本地伪码 `bridge-unreachable`**：扩展 background 在网络错误/超时（fetch 未拿到响应）时
**本地生成**的错误码（非桥面词表）。兼容约定：`GET /task` 的 30s 超时与 204 同义，
background 归一为 `{status:"ok", data:null}`（空轮询）；content 侧遇 `bridge-unreachable`
把面板状态切为「桥未连接（重试中）」并指数退避重试。

## 安装

1. 浏览器打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 打开右上角「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本目录（`extensions/gemini-bridge`）

## 使用步骤

1. 先启动桥服务（见上），再打开 https://aistudio.google.com 并进入对话页；
2. 确认页面右下角出现 gemini-bridge 浮动面板（状态「待命」）；
3. 「新对话自动注入协议」开启（默认）时，**切换或新建对话**后（URL 变化自动检测）
   插件检查当前对话是否为空：空对话页自动从桥服务拉取协议文本并回填
   （「自动提交回填消息」开则随后自动发送），对话应以工作区声明开头（其后为【human-agent 工具协议】）；
   已有消息的对话跳过不注入（防旧对话重放）。开关关闭、或**刷新页面后**（不自动检查），
   点面板「填入规则文本」手动注入；
4. 之后对 Gemini 的对话都会形成「回复 → 智能体执行工具 → 结果回填 → 提交」循环；
5. 任务完成或无需工具时 Gemini 直接输出最终回答，流程结束。

## 面板设置

「自动提交回填消息 / 新对话自动注入协议」为两项**独立开关**（面板中归为「自动模式」组），可任意组合；「未信任处置」为独立的三态选择器（见「权限模型」）。

| 设置 | 说明 |
|---|---|
| 自动提交回填消息 | 开（默认）：回填后随机延迟（防检测区间）自动点击发送；关：只回填，由你手动点页面发送按钮 |
| 新对话自动注入协议 | 开（默认）：切换到空的新对话页时自动拉取协议文本注入（自动提交开启则随后自动发送）；关：任何对话都不自动注入，用「填入规则文本」按钮手动注入 |
| 模拟人类输入 | 开：**分段粘贴 + 错别字纠错**（整段粘贴模拟 Ctrl+V，按概率预留错字 → 退格删除 → 停顿想字 → 逐字重打，段间随机停顿，纠错全程按真人键入节奏：纠错前停顿 1–2.5s、退格 150–450ms/次、重打 200–500ms/字）；关：一次性填入 |
| 提交延迟（秒，min/max） | 自动提交前的随机延迟区间，默认 3–8 秒；min>max 时自动对调 |
| 分块长度（字符，min/max） | 模拟输入时每块粘贴长度在区间内逐块随机（默认 2–1024，可调 2–1024，min>max 自动对调），避免等长分段暴露自动化；剩余不足 min 时并入前一块收尾 |
| 回填速度 | 回填节奏倍率（0.5x / 1x / 2x / 4x / 10x），默认 1x。**回填过程中修改立即生效**（每步停顿按当前倍率实时缩放；已切分好的块长度本次不变） |
| 未信任处置（三态选择器） | 未信任（黑名单/白名单外）调用去向——默认弹窗（默认）：逐条人工授权；默认拒绝：一律拒绝，无人值守推荐；默认允许：一律放行、仅黑名单兜底（选此项时面板常显 ⚠ 警示）。旧「自动授权危险命令」开关（`autoApprove`）一次性迁移：true→默认允许 / false→默认弹窗（行为不变） |
| 审批超时（秒） | 弹窗倒计时，到点自动全部拒绝；默认 120，可调 10–600 |
| 纠错概率（%） | 每段触发「粘贴错字→退格→重打」纠错的概率，默认 40%，可调 0–100 |
| 候选粒度（信任候选折叠区） | 「入库所选」的粒度：此路径（`self`）/ 此目录（`subtree`）；随 `{items, scope}` 提交，由桥服务物化条目并按工具类型校验；响应 `grants` 四状态计数（新增/重复/已被覆盖/被拒）汇总入日志 |
| 桥服务地址 | 默认 `http://127.0.0.1:8765`，可改（纯端口如 `9876` 亦可）；改动后保存在 `chrome.storage.sync` |

面板交互：标题栏**按住可拖拽**（悬浮球同样可拖），右上角 **–** 按钮收起为**悬浮球**（仅保留状态圆点，双击展开完整面板）；收起/展开时位置保持，扩展功能不受面板状态影响。日志栏带**导出**（下载为 `.log` 文本文件）与**清除**按钮；自动提交前状态行显示**动态倒计时**（逐 0.1s 递减）；「自动提交回填消息」行右侧的**「立即提交」按钮**无条件提交输入框当前内容（非空即提交、无论内容是回填还是用户自输入；输入框为空或回填进行中时按钮置灰禁用）。面板/悬浮球为边框样式，原生控件（数字输入 spinner、select 下拉、滚动条）走暗色绘制。面板另有「工作区」行（显示桥当前工作区，取自 `GET /agent/info`；桥未连接时显示「（未获取）」，连接成功后自动补拉）与「信任候选」折叠区（展开拉取候选列表，单选/多选 + 粒度（此路径/此目录）「入库所选」一键写入白名单并核销，响应 `grants` 计数汇总入日志；或「清除所选」显示删除条数；标题计数徽标随裁决更新）。

## 权限模型

所有工具调用一律走服务端统一权限域裁决（`createPermission`：黑名单 + 白名单 + 规范匹配键管道），扩展只呈现审批交互：

| 档位（未信任调用去向） | 裁决 |
|---|---|
| **默认弹窗**（默认） | 黑名单直接拒绝（不下发审批）→ 白名单命中静默执行 → 其余下发弹窗逐条人工授权（白名单按钮按载荷 `options` 渲染：此路径/此目录） |
| **默认拒绝** | 未信任一律拒绝（桥标准拒绝文案回填），适合无人值守；黑名单不命中即回「拒绝」 |
| **默认允许** | 未信任一律放行，仅黑名单兜底（放弃边界，面板常显警示） |

- **黑名单**：内置随软件版本（`src/permission/blacklist.ts`），只拦**确定性系统破坏**操作——系统盘/根目录递归删除、格式化、整盘擦除、块设备直写、Boot 关键文件/注册表、杀之必崩进程，以及写类工具写系统目录两条形态（`System32`/`Boot` 子树、`System Volume Information`）**仅写类工具命中**——读 System32 不硬拒，走信任门禁。目标锚定（`rm -rf C:\Windows\Temp` 等可恢复目标不入）；命中直接拒绝回填「已拒绝（blacklist：黑名单命中…）」，**不下发审批**。用户可手改该文件（责任自负，升级被覆盖属已知行为）。
- **白名单**：`~/.human-agent/whitelist.json`，文件格式 **v1**：`{version:1, workspaces:{<工作区匹配键>: [...]}}`（与 `candidates.json` 共用同一容器格式；`version` 不是 1 或文件损坏 → 整档按空载入，**无迁移代码**——旧格式文件不再读取）。条目 `TrustEntry` `{tool, key, scope}`：`scope:"self"` 目标键精确匹配；`scope:"subtree"` 段级前缀覆盖子树（目录条目以 `/` 结尾：`src/` 覆盖 `src/utils.ts`、不覆盖 `src-evil/`），并覆盖条目自身（`w/` 匹配 `w`）。**写信任蕴含读**：写条目同时覆盖同目标读类调用，读条目不覆盖写；写入时自动冗余清理（加父去子、子被父盖跳过）。
- **规范匹配键管道**：路径类参数一律以工作区为基准 `resolve` → realpath 深度归实（junction/symlink 别名收敛）→ win32 小写（`matchKey`）。相对路径写入落在工作区内（判界内、静默），相对穿越到系统目录会被归实后命中黑名单；realpath 失败按未信任处置。执行落点 = 判定落点（执行用 realpath 后的 `execPath`；命令执行 cwd 钉工作区）。
- **工作区**：`--workspace` > `HUMAN_AGENT_WORKSPACE` > 启动 CWD；启动 realpath 规范化且必须已存在；一进程一工作区（切换=重启）。工作区自动注册为写白名单子树条目（界内写入静默）；工具协议文本以**工作区声明**开头（其后为【human-agent 工具协议】），告知智能体活动边界（软约束）。面板「工作区」行显示当前值（`GET /agent/info`）。
- **信任候选**：白名单外一切裁决由**桥自记**（`~/.human-agent/candidates.json`，与白名单同容器格式按工作区分节，聚合 `(tool, key)` 计数 `deny-count`/`allow-count`，容量帽 200 条/30 天）。面板折叠区「信任候选 (N)」单选/多选一键入库（粒度此路径/此目录，发 `{items, scope}`），入库即核销；也可「清除所选」。默认拒绝档 = 补种清单；默认允许档 = 放行审计。黑名单命中、白名单命中、close 释放不入档。
- **弹窗交互**：逐条 [允许] [拒绝] + 白名单按钮（**按审批载荷 `options[i]` 渲染**：两项 → [白名单(此路径)] [白名单(此目录)]，一项 → [白名单]，零项 → 无按钮；白名单即允许）；「全部允许 / 全部拒绝」保留（全部允许不自动入白名单——白名单始终是显式按钮动作）；所选条目经 `POST /task/approval` 的 `whitelist` 字段**原样回显**，桥侧按批校验（条目必须与某条 `allowed=true` 调用的选项成员逐字段一致，否则 400 且不落盘）。弹窗倒计时到点自动全部拒绝（回填「审批超时，未执行」）；审批请求在桥服务侧另有 600s 兜底超时（防扩展崩溃）。

**状态标准**（跨网页通用：这套状态机描述「捕获 → 后端执行 → 回填 → 提交」桥流水线，与具体前端无关，
将来接 ChatGPT 等其他网页可复用同一套；自动/手动提交的差异只体现在「待提交」阶段的渲染上）：

| 阶段 | 显示 | 颜色 |
|---|---|---|
| 静息 | 待命 | 蓝 |
| 回填 | 回填中（模拟粘贴） | 橙 |
| 待提交 | 自动：自动提交（Xs 后）倒计时；手动：待提交（手动发送） | 绿 |
| 回复在途 | 等待回复（请求发出即置位，原文到手结束） | 紫 |
| 后端处理 | 已抓取回复（等待执行） | 青 |
| 审批 | 等待授权 | 琥珀 |
| 桥故障 | 桥未连接（重试中） | 琥珀 |
| 异常 | 错误（投递循环空闲时清回待命） | 红 |

状态行文字与右侧**呼吸灯**、悬浮球圆点同色，均带呼吸律动动画。

**注意**：请只在一个 AI Studio 标签页使用本扩展；多个标签页会竞争轮询同一条回填消息。

## 排查

| 现象 | 可能原因 / 处理 |
|---|---|
| 面板状态「桥未连接（重试中）」→「桥未连接」，日志「桥服务不可达：桥未连接或请求超时」 | 扩展本地伪码 `bridge-unreachable`（网络错误/超时，fetch 未拿到响应）：桥服务未启动（先 `GEMINI_BRIDGE_PORT=8765 pnpm dev`）；端口占用（换端口后同步改面板「桥服务地址」与 `manifest.json` 的 `host_permissions`）。自动指数退避重试 5 次后可点面板「手动重试」 |
| 回填后输入框无反应 / 无法提交 | 页面未在对话页（无 `ms-prompt-box textarea`）；或页面 DOM 结构更新导致选择器失效 |
| 回填失效（未找到输入框/发送按钮） | 打开 DevTools 检查元素，更新 `content.js` 顶部选择器常量区域：输入框 `ms-prompt-box textarea.cdk-textarea-autosize.textarea`、发送按钮 `ms-run-button button[type="submit"].ms-button-primary`。AI Studio 为 Angular SPA + 虚拟滚动，元素频繁创建/销毁，抓取必须每次现查 DOM |
| 回复不再回传（无「已回传」日志） | 响亮停滞诊断：无「网络捕获已挂载」→ 注入层未生效（Chrome < 111 不支持 `world:"MAIN"`；或扩展代码更新后未刷新 AI Studio 页面，content script 不热重载）；有「检测到 GenerateContent 请求」但无「已回传」→ 解码失败（看「解码失败（原文 N 字符）」日志）或 AI Studio 端点迁移（更新 `inject.js` 的 URL 命中判据）。**捕获链路逐环可诊**：浏览器控制台过滤 `[ha-capture]` 可见全链路（open 命中 → send 命中 → readyState 轨迹 → 快照兜底（rs3/rs4/abort/loadend 来源标签）→ done），断在哪一环一目了然；出现「readyState 归零」或「abort() 在原文到手前被调用」（附调用栈）警告 = 请求对象在原文到手前被页面重置、本次捕获被吞——携警告与调用栈报告 |
| 插件加载时报错 | `chrome://extensions` 页面点「错误」查看 background 日志；确认四个文件（background.js、content.js、inject.js、decode.js）无语法错误 |
| 新对话后协议文本未注入 | 先确认「新对话自动注入协议」开关为开（默认）。开启时自动注入由**会话切换**触发（URL 变化检测）且仅在**新对话页**（地址为 `/prompts/new_chat`、轮次计数 0、双采样确认；轮次不计思考）时执行；**刷新页面后不自动检查**，请点面板「填入规则文本」（任何开关状态下都可用）。日志「保守等待渲染…」= 新对话页出现会话容器（首条消息提交过渡态），稍候或手动注入。拉取失败原因见日志：桥未启动 / 旧版桥服务无 `/agent/protocol` 端点（需重启桥服务加载新代码）|
| 旧 whitelist.json / candidates.json 内容失效（升级后同调用重新弹窗/被拒、候选清空） | 文件格式升级为 v1（`{version:1, workspaces}`）——旧格式文件不再读取（损坏或 `version ≠ 1` 一律整档按空载入，属安全向设计，无迁移）。确认可信后经弹窗白名单或信任候选重新入库即可 |
| 信任候选区拉取失败（日志：`未知端点：/permission/candidates`，`error.code:"unknown-endpoint"`） | 桥服务未加载新代码（旧版桥无 `/permission/*` 端点），重启桥服务 |
| 入库所选返回 400（日志「信任候选入库失败：<服务端 message>」） | 服务端 message 直接显示；常见于对不支持子树粒度的工具选「此目录」（message 会指明具体条目）。所选条目为扩展原样回显，正常路径不会出现条目非法 |
| 工作区行显示「（未获取）」 | 桥未连接时的占位；连接成功后自动补拉（刷新页面亦可） |

**扩展重载**：修改扩展代码后需在 `chrome://extensions` 点刷新，并**刷新 AI Studio 页面**（content script 不热重载），否则仍跑旧代码。

## 安全

权限矩阵保证**无人值守也安全**：黑名单（确定性系统破坏）各档一致直接拒绝、不下发审批；未信任调用
按面板「未信任处置」档位执行——默认弹窗逐条人工授权（默认拒绝/默认允许档为策略代答；默认允许放弃
边界、仅黑名单兜底），拒绝/超时说明随结果消息回填；
弹窗倒计时到点自动全部拒绝，审批请求在桥服务侧另有 600s 兜底超时（防扩展崩溃）。
